# LWB Bridge for DSH Tavern

**公开测试版候选 `0.1.0-beta.11`**。面向 [flizzywine/dsh-tavern](https://github.com/flizzywine/dsh-tavern) 插件 API 7／8 的第三方状态与记忆扩展：受限 State2、便携记忆包预览导入导出、手动总结候选和三个只读宏模板。

**Based on LittleWhiteBox by biex** — 原项目 **[LittleWhiteBox（小白X）](https://github.com/RT15548/LittleWhiteBox)**。本项目是其部分数据层的公开修改适配，产品名称为 **LWB Bridge**，并非原作者或 Tavern 官方发布。包 ID 保留 `dsh-tavern-lwb` 以兼容已安装用户的数据。

## 安装

在 DSH Tavern 打开 **设置 → 酒馆插件 → GitHub 地址**，粘贴：

```text
https://github.com/Sophiacyl/dsh-tavern-lwb
```

连不上 GitHub 时，在本仓库选择 **Code → Download ZIP**，回到同一页面点「上传 ZIP」。源码树包含完整运行文件，无需用户运行 npm 或构建。安装后按提示刷新或重启；更新已加载的宿主代码后需要重启 DSH。

插件页签名称为 **LWB Bridge**。只做有限协议适配，不支持直接运行完整原版小白X或全部依赖它的旧卡。

## 已验证和待验证

- 自动化：State2／记忆／工具提交／面板回归，真实公开 API 7／8 模块的合成集成，Chromium 390×844 触摸滚动与底部按钮。
- 用户实机反馈：升级、滚动、变量90／5、重复处理、记忆导入导出、总结候选的完整采用均已通过。
- 待补：记忆出现在后续实际正文请求中的检查（此前被独立正文问题阻挡），长期主存档和更多模型兼容性。上述实机反馈不作为所有设备／供应商都通过的保证。
- 状态历史受宿主每局按轮记录数量/总字节与全链扫描性能限制，10,000条只是内部保护阈值；未采用候选最多持久化15分钟。总结支持逐项增量审核，完整边界见下文。

## 从已有 alpha／beta 更新

1. 保留现有插件和数据，使用 **设置 → 酒馆插件 → 上传 ZIP** 上传 beta 包，同名更新。
2. 按宿主提示重启 DSH，再打开侧栏「＋ → 插件 → LWB Bridge」（旧名“小白状态”）。不要先卸载旧插件。
3. 原有变量和启用开关继续读取，**不需要重新初始化**。例如此前生命值 90／金币 5，应仍显示 90／5。
4. State 与记忆两个页签现在都由面板自己滚动，底部为“返回故事”浮钮留出空间。

旧状态记录在读取时保持原样；新写入才保存为包含独立 `state`／`memory` 分区的记录。beta 写入后不要直接降级回 alpha，旧版不识别新分区格式。升级前可用原版「导出 JSON」留一份状态副本；它可在“状态恢复与历史回放”中先预览再确认恢复。

## State 状态页

已有 alpha 功能继续保留：

- State2 的赋值、数值增减、数组追加／按值移除、字段删除，`$schema/$range/$step/$ro/$enum` 受限规则。
- 每局显式启用，初始化先预览再确认；普通回复的闭合 `<state>` 在结算后处理。
- 按轮与正文版本保存完整快照，去重、回退、候选切换、分叉与宿主存档映射。
- 独立变量服务，不写 MVU `stat_data`，不接管官方 MVU 结算。

第一次使用请在新测试游戏的开场白启用、预览并确认面板自带的生命值／金币样例。后续回复可输出：

```text
<state>
数据.角色.生命值: -10
数据.角色.金币: +5
</state>
```

数字带正负号表示增减；赋值负数写 `(-5)`。规则拒绝可形成 partial，合法项保留、诊断列出拒绝项；格式／安全／容量错误整批回滚。开场白、安装或开启前的历史不会自动补跑。处理已有当前回复时，必须已有更早的初始化基线。

插件自身取消了 128 份连续记录的硬停止，仍逐条验证完整父链；较早轮被编辑、替换或补写后，失效后续记录显示 `LWB_PARENT_CHANGED`。**10,000 条只是插件内部父链保护阈值，不是已验证的可用游戏长度**：锁定参考 Tavern 另限每插件每局 2,000 条按轮记录、合计 8 MiB，不同正文版本也占记录。实际容量取决于快照大小和宿主版本，可能更早达到上限。尚未实现高效检查点；读取成本随历史增长，长篇正式使用前需备份并实测性能。已有状态保留导出入口。

## 状态恢复与受控历史回放

State页的“状态恢复与历史回放”支持粘贴Bridge v1状态导出包，先预览再明确确认。确认只替换当前轮State分区并建立新基线，不改同轮记忆，不改写以前各轮；较晚旧快照可能失效，操作前先备份。

上游当前状态可人工整理为下列显式封装（不是原作官方导出格式）：

```json
{"spec":"dsh-tavern-lwb/upstream-snapshot","version":1,"variables":{"数据":"{\"金币\":10}"},"roots":["数据"],"LWB_RULES_V2":{}}
```

仅解码`roots`指定的字符串根，不搬入其它宿主变量。规则表必须明确提供，空表表示不迁移约束，不从值推测规则。空根、损坏JSON根、超限值、危险键和不支持规则拒绝；原readonly规则作为快照保留，不通过执行赋值绕过。完整metadata、检查点、脚本不作为导入格式。

也可提供显式消息WAL封装：`{"spec":"dsh-tavern-lwb/upstream-wal","version":1,"records":[{"v":1,"entries":[...]}]}`。records仅含用户选定的一条分支按楼层顺序的State2消息记录（最多100条、128个entry，整个JSON64 KiB）。逐entry保留text/call顺序、roots归属和内部pop语义；指纹只检查格式，不证明原文真实性。不能完整执行的条目整批拒绝，不静默接受partial。原版可保留守卫拒绝请求、未归属text副作用及旧重复数组删除；这些历史边缘记录当前可能被严格拒绝，不称完整无损WAL迁移。每entry最多128操作/128规则，整个封装还受节点、深度和字节限制。结果仍只建立当前轮新基线，不迁移原楼号、swipe候选集合或检查点。

历史回放输入初始化文本和已完成轮次范围（最多100轮、正文总计256 KiB），只处理严格闭合`state`块；任何partial/failed或旧`plot-log`/`varevent`协议都会停止预览，不写数据。确认时重新核对全部原文摘要、正文版本和状态基线；旧轮改变则拒绝。预览15分钟有效，不自动调用模型。

**兼容边界**：API7/8没有公开宏注册/原生提示词转换接口，既有卡/世界书/历史的宏无法透明接入；目前仍只处理显式模板。`plot-log`的push去重、根删除与State2不同，`varevent`含JS条件和执行，不做无损自动转换；范围清单见本地第4步兼容报告。

## 记忆页：导入和导出

1. 打开「记忆」页签，选择小白导出的 JSON 文件，或粘贴完整 JSON。
2. 点「预览记忆 JSON」，核对内容、条目数、原有条目数与警告。
3. 点「确认替换记忆」，在二次确认中同意后才写入。
4. 点「开启记忆」后，后续普通 Tavern 正文请求将收到有界的核心事实／相关条目。
5. 「导出记忆 JSON」输出同一种小白便携记忆包。

支持 `type: "LittleWhiteBoxStorySummaryMemory"`、`version: 1` 的便携包。事实使用中文键 **人物名字／种类／描述／核心事实／趋势**；内部 `s/p/o` 存储快照、聊天 metadata 和裸数组不作为导入格式。

首版保留关键词、事件、主要人物、别名、角色弧光和持续事实。原楼层归属、向量、旧维护／撤销历史不迁入，识别到相关字段会在预览提示；未知字段和超限包明确拒绝，不悄悄丢内容。

最小示例：

```json
{
  "type": "LittleWhiteBoxStorySummaryMemory",
  "version": 1,
  "data": {
    "facts": [
      {"人物名字":"小雪","种类":"职业","描述":"医生","核心事实":true}
    ]
  }
}
```

导入替换的是当前轮版本上的记忆；同轮状态保持不变。记忆会随宿主当前剧情版本读取，回退至导入前不可见，切回对应版本恢复；分叉／游戏存档由宿主映射。记忆开关及宏模板属于整局设置，不随回退改变。

## 手动总结：先候选，后采用

在记忆页选择 **1–20 个已完成轮次**，点「生成记忆候选（使用模型额度）」。确认框会说明使用本局后台模型，宿主可能额外附带人物卡、世界书及最近剧情；确认后才启动一次手动任务。

- 所选剧情正文总计最多 14000 字符，过长时请缩小轮次范围。
- 模型读取当前记忆与所选剧情，提交完整便携 JSON 提案；原有记忆始终不变，直到你确认采用。
- 面板展示普通新增、旧条目保留项和潜在冲突。未出现在提案里的旧条目自动保留，不会因总结省略而删除。
- 新事实如与现有同一人物和类别的事实相关，默认不追加；逐项核对后勾选才追加。其它集合遇到同一键内容变化时默认保留旧值，明确选择后才替换。
- 点「确认采用已选增量」后才写入；提交前再次核对生成时记忆 revision 和正文版本。期间记忆被导入或编辑，候选会冲突失效，不覆盖后来的内容。
- 不满意可丢弃候选。导出备份仍建议保留；增量合并不会替你判断剧情事实是否真实。
- 停止、版本变化、卸载、格式错误不自动重试，也不改用别的模型。完整候选和合并预览持久化在当前游戏的插件设置中，最多保留 15 分钟；刷新页面或重启 DSH 后可恢复。逐项选择保存在页面状态中，页面关闭后需重新审核；候选本身不会因此前未确认的选择被自动采用；恢复后普通新增按默认值选中，相关事实默认不选，字段替换默认不选，需再次审核。超过期限、正文版本变化或基线记忆 revision 变化时会删除草稿并显示过期／失效状态。
- 每次用户确认生成一个随机确认 ID，宿主先保存已接纳回执再启动任务；同 ID 的网络重发不会重新发起模型调用。启动结果不明或失败后，要再试需用户重新确认。本局最多保留 128 次确认回执，不自动清理后重放。

模型通过 `memory_submit` 工具提交结果，工具包含六类记忆的完整结构。每次调用都先做格式和容量校验，再返回 `ok:true`；例如别名误用 `name/alias` 会返回 `ok:false` 与 `from/to/evidence` 修正提示。模型可在同一后台任务内修正重交；这可能增加该任务内部的模型步骤，插件不会自动新开一次总结任务。

合法工具回执表示记忆数据已校验，只有后台任务正常完成并通过版本检查后，才会出现待采用候选。提示词要求模型在提交后输出简短收尾句；若宿主未完成文本收尾或传输失败，本版不采用中断结果，并显示失败原因。未调用提交工具时，完整最终 JSON 文本仍可作为兼容回退；无效工具调用不会被普通结束语掩盖。

面板现在独立显示 **排队／生成中／待采用／失败／取消／过期／失效／已采用／已丢弃**，失败不会再只表现为“暂无候选”。状态摘要和未采用候选均持久化在插件整局设置；重启后可恢复候选并继续审核。候选超过15分钟、正文版本或基线记忆发生变化时会清除草稿并显示对应状态。未知服务错误原文和未知错误代码不会直接显示，详情留在宿主任务记录。“刷新记忆”在后台忙碌时也可执行只读刷新。

模型摘要仍需人工审核，可能漏记或误记。自动测试不发送真实模型请求。早期测试发现工具回执先于字段校验的问题，现已改为即时校验、修复提示与可见任务状态；别名等错误结构不会提前返回成功。

## 三种受限小白宏

在「记忆注入模板」填写模板并保存：

```text
当前生命值：{{xbgetvar::数据.角色.生命值}}
角色资料：
{{xbgetvar_yaml::数据.角色}}
```

支持 `xbgetvar`、`xbgetvar_yaml`、`xbgetvar_yaml_idx`，安全读取本插件状态的点路径、简单数组下标、上游旧卡支持的裸括号键和引号对象键，例如 `人物[名字]`、`人物["名字"]`、`A[0].name`。宏名及路径两侧空白会修整。**仅在此模板展开**，不注册宿主全局宏、不改写人物卡、世界书或预设中的旧宏。仍拒绝负下标、表达式、空格/转义复杂键、原型键、写入宏和全局变量宏；未知／畸形宏显示诊断提示并跳过本轮模板。需要本游戏已有有效状态基线。

模板和导入记忆仅按数据处理，不执行 JS、EJS、taskjs、命令或工具。动态状态值不会被二次当作模板执行。

## 支持范围与容量

- 上下文贡献适用于 **普通 Tavern 游玩请求模式**；宿主 SillyTavern 兼容请求模式不调用这些贡献接口。
- 不含小白 OS、任意脚本、旧版 plot-log／varevent、向量检索、自动记忆维护、旧卡全局宏兼容或完整初始化任务迁移。
- 记忆包 UTF-8 最多 **48 KiB**，全部集合及嵌套条目合计 **200 项**，单字段 4000 字符，结构深度 16；超限拒绝不截断。导出文件也遵守同一上限。
- 每轮状态和记忆合计最多 **62 KiB**，宿主单条记录上限为 64 KiB。状态引擎仍限 48 KiB、128 操作／规则、深度 20／4000 节点；变量注入 JSON 约 6800 字符。
- 记忆注入选取最多 3000 字符，优先核心事实及与本轮输入相关条目，不保证全部记忆每轮常驻。检索仅取输入前 4000 字符作相关性线索，不改玩家输入。
- 宏模板最多 4000 字符，展开最多 8000；整个记忆／宏贡献最多 7400 字符。过长时明确提示而不截断成残缺模板。
- 不接受原型链键、复杂对象、YAML anchors／aliases／自定义 tags、非有限数、访问器等。

## 数据和权限

运行代码通过公开 `tavern` 接口读写自身插件数据，不读 Tavern 数据目录或任意本机文件，不调用手机接口或 shell。状态／记忆使用同一按局写入队列避免互相覆盖。全局 Node 插件的总体权限仍由 DSH 环境决定。

状态导出、记忆导出会包含用户主动放入其中的内容；不要把密钥存作变量或记忆。导出包不主动加入完整聊天、卡库、凭据。总结会向已配置模型发送选中剧情及宿主附带背景，只有明确点击确认时发生。

## 开发和验证

运行时零外部 npm 依赖；YAML 和 State2 必要代码随包提供，React 使用宿主模块加载器。测试依赖和浏览器只在工作区，均不进入 ZIP。

开发环境：Node.js 24；本仓库安装插件无需依赖，以下仅供开发测试。所有测试依赖和固定公开参考源码均在 `tests/` 下显式准备：

```sh
npm ci --prefix tests/runtime --ignore-scripts
npm run test:prepare
npm run test:all
npm run check
npm run pack:zip
```

Chromium触摸布局需额外按 [tests/README.md](tests/README.md) 准备测试浏览器，然后运行 `node tests/mobile-layout.mjs`。测试不启动真实酒馆或调用收费模型。

真实 API 7／8 模块在合成存储上验证；React/JSDOM 验证交互，Chromium 手机尺寸侧栏验证滚动和底部按钮。本仓库不发布用户设备截图或私人存档；开发测试环境不读取用户现用profile。实机反馈与待验证范围分别列在文首。
